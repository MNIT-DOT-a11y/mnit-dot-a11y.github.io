Accessibility defects found late are costly to fix and often require design or architecture changes. Building accessibility into every phase of the software development lifecycle reduces rework, shortens remediation cycles, and makes accessible releases predictable instead of a last-minute scramble.

This lesson shows where accessibility belongs at each stage (requirements, design, development, code review, CI/CD, QA and UAT, release and monitoring) and what QA contributes: reviewing user stories for accessibility acceptance criteria, running manual scripts for keyboard, NVDA, zoom, and color, confirming automated scan results, and applying release criteria that block high-severity findings. It also covers the dashboards and ownership that keep accessibility measurable over time.
